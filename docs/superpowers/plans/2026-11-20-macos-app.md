# GestureDeck macOS App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an Apple Silicon `GestureDeck.app` that starts the existing server, opens the presentation workspace in a native window, and bundles everything needed to run without Terminal or a separately installed Node.js.

**Architecture:** A small SwiftUI app hosts the current workspace in `WKWebView` and runs a bundled ARM64 Node process for `server.mjs`. A macOS-only build script copies the required server and browser assets into the app bundle. The Vercel site build gets its own `dist/site` output so its cleanup and deployment cannot erase or expose `dist/macos/GestureDeck.app`.

**Tech Stack:** SwiftUI, AppKit, WebKit, Swift compiler (`xcrun swiftc`), bundled Node.js, vanilla JavaScript, Node.js test runner, Vercel static output.

**Tracking issue:** [wehyn/GestureDeck #12](https://github.com/wehyn/GestureDeck/issues/12)

---

## File map

- Create `macos/Sources/GestureDeckApp.swift` for app lifecycle, child server startup/shutdown, status and error UI, the `WKWebView`, and the PDF open-panel delegate.
- Create `macos/Sources/ServerLifecycle.swift` for the buffered startup-line parser and deterministic exit messages used by the app.
- Create `macos/Tests/ServerLifecycleTests.swift` as a dependency-free Swift self-check for chunked readiness output and server exits.
- Create `macos/Info.plist` for the app identity, macOS minimum, local-network explanation, and loopback HTTP allowance.
- Create `scripts/build-macos.mjs` to assemble `dist/macos/GestureDeck.app`, copy the current ARM64 Node executable and allowlisted runtime assets, compile the Swift app, and verify the result.
- Modify `package.json` to add `npm run build:macos` and include the build script in `npm run check`.
- Modify `scripts/build-vercel.mjs`, `vercel.json`, `tests/build-vercel.test.js`, and the README so the website uses `dist/site`; keep the macOS bundle out of Vercel's published output and out of website-build cleanup.
- Do not change `server.mjs` or `src/mobile-remote-server.js`; the Mac app must keep using their current path, realpath, host, origin, peer, and private-interface checks.
- Do not modify the Chrome extension; Canva control remains in Chrome as specified.

- [x] **Step 3: Add lifecycle parsing and exit handling**

Create `macos/Sources/ServerLifecycle.swift` with `ServerState` (`starting`, `ready`, `failed(String)`), a small buffered stdout parser that returns true only when a complete line starts with `GestureDeck listening on `, and a `ServerLifecycle` state machine used directly by `AppDelegate`. Its `processTerminated(shutdownRequested:)` method must transition `.starting` to a port-conflict failure, `.ready` to a stopped-server recovery failure, ignore intentional shutdown, and ignore termination callbacks after `.failed`.

Make the `Process.terminationHandler` call the same `ServerLifecycle.processTerminated(shutdownRequested:)` transition that the Swift self-check calls. The startup message should explain a port `5173` conflict; the post-start message should say the local server stopped and to reopen GestureDeck. Have `fail(_:)` move either `.starting` or `.ready` to `.failed`, but ignore duplicate failures and intentional app shutdown. Clear the pipe readability handler after failure or shutdown. Set an `isShuttingDown` guard before calling `Process.terminate()` in `applicationWillTerminate`.

- [x] **Step 4: Add the SwiftUI app shell**

Create `GestureDeckApp.swift` using SwiftUI's `@main` app entry point with an `NSApplicationDelegateAdaptor`. Use a resizable window with a useful minimum size. Show a launch state until the server reports successful startup, then show the workspace `WKWebView`; show a readable error view if startup fails.

The `AppDelegate` must launch `Bundle.main.resourceURL/GestureDeck/node` with `Process.arguments = ["server.mjs"]`, `Process.currentDirectoryURL` set to the packaged `GestureDeck` directory, and `Process.environment["HOST"] = "0.0.0.0"` plus `Process.environment["PORT"] = "5173"`. Read the child's stdout and only signal readiness after receiving the existing `GestureDeck listening on ...` line from `server.mjs`. If the process exits first, show a startup error that explains how to resolve a port `5173` conflict. Never load `127.0.0.1:5173` before this readiness line, because it may belong to another service.

Retain the `Process` for the app lifetime. In `applicationWillTerminate`, call `Process.terminate()` so Node receives SIGTERM and the existing server's SIGTERM handlers close phone and cloud sessions. If startup fails, stop the child and keep the error visible rather than leaving a server process running.

- [x] **Step 5: Host the workspace with a PDF file picker**

Implement a macOS `NSViewRepresentable` around `WKWebView`; load `http://127.0.0.1:5173/workspace.html` only after readiness. Implement `WKUIDelegate.webView(_:runOpenPanelWith:initiatedByFrame:completionHandler:)` with `NSOpenPanel`, `UTType.pdf`, and the WebKit request's multiple-selection setting so the existing PDF input works from the app window.

Do not add a JavaScript bridge or duplicate presentation controls. Canva is not exposed in this WebKit window; it continues to use the existing Chrome extension in Chrome.

## Scope and deployment notes

- App output remains at `dist/macos/GestureDeck.app`, as approved in the design. Site output moves to `dist/site/`, and `vercel.json` publishes only that directory.
- The app build is macOS-only and is not added to the current Ubuntu GitHub Actions job. Its build script must fail clearly on other platforms; the existing cross-platform checks continue in CI.
- Do not bump `extension/manifest.json`; the Chrome extension is unchanged.
- No new server route, pairing payload, dependency, installer, icon, auto-update mechanism, signing, or notarization is in scope.
